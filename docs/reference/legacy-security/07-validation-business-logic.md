| 2.3.4 | Gap-free numbering under concurrency; cancelled numbers never reused | `assignNumber(tx, scope)` — serialized per scope (advisory lock). **The PRECONDITION landed 05/08/2026 [DC-15] `fd41517`, and only the precondition:** challan numbers are globally unique across works only if a work code is never reused, so `migrations/0060_work_code_letter_number_unique.sql` adds `works_tenant_id_work_code_key` and `works_tenant_id_letter_number_key` as **plain, non-partial** `UNIQUE` table constraints — deliberately not `WHERE deleted_at IS NULL`, so a soft-deleted work keeps its code forever and cannot free it for a new work whose `<work_code>-DC` prefix (PRODUCT-SPEC.md §7) would then collide. All six corpus letters reconcile exactly (`diff = 0`, no flag), so the tolerance band is defensive rather than corpus-exercised.
