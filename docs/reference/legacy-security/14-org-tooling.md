## 12A. Org tooling (outside certified product scope)

These rows cover **internal org tooling only** — the static GitHub Pages CEO
dashboard in `docs/` (plain ES modules, no build step, operated by the CEO in
their own browser). It is **not part of the certified Auto-MB product surface**
and is out of audit scope; ASVS IDs below are cited as the nearest analogue,
not as certified product controls. It is listed because AGENTS.md rule 1 says
"module" without qualification, and because the dashboard sits on the
**governance control path**: it writes `decisions/*.md`, and a bound
`APPROVED-*kernel*.md` decision file is precisely what lifts the
`packages/kernel` freeze in `.claude/hooks/guard.sh` (bound, since
`decisions/APPROVED-013`, to a set `$CLAUDE_TICKET` named on a whole-token
`Authorizes:` line of an `APPROVED` decision whose `Scope:` line covers the
path — never to bare filename existence, and never to a branch diff; an unset
`$CLAUDE_TICKET` always blocks). **Correction, 28/07/2026:** "on a whole-token
`Authorizes:` line" overstates the binding. Both lines are located by
line-anchored greps over the *entire* decision file, so they bind from inside
an HTML comment, a fenced code block or a prose counter-example just as well as
from the header — see the markdown-blind row in the table below, and
`decisions/APPROVED-023`. **Corrected again later the same day:** APPROVED-023
(Option A) landed — both fields are now read solely from the decision's header
block (`decision_header_scan` in `.claude/hooks/frozen-paths.lib.sh`), so the
original claim finally holds, and holds stronger: the binding is to header
fields, not to matching lines wherever they appear.
